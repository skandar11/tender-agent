# Операция — проверить фирму по БИН

**Когда:** «проверь фирму <БИН>», «кто это такие», «сколько у них договоров в этом году»,
«были ли в недобросовестных», «сравни нас с конкурентами по лоту», «разбери протокол итогов».

**Что спрашивает комиссия.** В «Протоколе об итогах» конкурса у каждого участника стоят
условные скидки: уплаченные налоги, нахождение в области работ (территориальность),
аудированная отчётность в депозитарии, отрицательные значения по договорам и по РНУ,
реестр отечественных товаропроизводителей; и в расчёте условной цены — финустойчивость,
сумма договоров по предмету за текущий год, число действующих договоров. Проверка фирмы
собирает то же. Правило — [[pravilo-uslovnye-skidki|условные скидки]].

**Шаги:**

1. **Одна фирма** → `firm.py check <БИН> [--word <предмет>]`: кто и где (КАТО), договоры
   финансового года по последней редакции (допсоглашения не двоят, «не заключён» не
   считается), действующие, по предмету — если дано слово; расторжения в одностороннем
   порядке, «не заключён» и «по суду» за 5 лет; РНУ — сейчас (API) и все прошлые включения
   (сайт портала).
2. **Несколько фирм** (мы и конкуренты) → `firm.py table <БИН> <БИН> … --word <предмет>
   --region <две цифры КАТО области работ> --csv <файл>`: таблица в столбцах протокола итогов.
3. **Конкурс прошёл** → `firm.py protocol <номер объявления> --csv <папка>`: что комиссия
   поставила каждому — скидки, условные цены, финустойчивость, победитель, второе место.
4. **Что комиссии ставили этой фирме раньше** → `firm.py history <БИН>`: её строки из
   протоколов итогов конкурсов, где у неё договор в этом году.
5. **Покажи** таблицей; нет данных — так и пиши, с источником, где их взять.

**Чего нет без людей:**
- **Налоговый орган и уплаченные налоги** — только API КГД по ключу `X-Portal-Token`
  (`secrets/kgd-token`); ключ выдаёт КГД по обращению фирмы на portal.kgd.gov.kz.
  Пока ключа нет — место по КАТО из госзакупа (это адрес регистрации, не налоговый орган).
- **Аудированная отчётность в депозитарии** — dfo.kz, API не найден; смотреть руками.
- **«Отрицательное значение по договорам» в смысле Правил** — скрипт показывает факты
  реестра (расторжения, «не заключён», по суду); как их считает комиссия — по правилу
  [[pravilo-uslovnye-skidki|условные скидки]] и по протоколам (`history`).

**Крайние случаи:**
- Протокол лежит PDF, не HTML (старые закупки) — скрипт говорит об этом и даёт путь к
  файлу; текст — `extract_docs.py`.
- API ответил 403 — токен привязан к адресу машины (`ows.py check`).
- Сайт РНУ не ответил — ссылка на страницу поставщика печатается, открыть руками.

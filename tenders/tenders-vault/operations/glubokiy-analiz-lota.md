# Операция — глубокий анализ лота (работы и услуги)

**Когда:** «глубокий анализ лота <номер или ссылка>», «анализ лота …», «разбери лот …», «полный разбор …».

**Как:** все шаги подряд, одним прогоном. По ходу владельцу вопросов не задавать. Документы скачивает агент
сам, сразу в папку лота: владелец ничего не скачивает и ничего не нажимает. Чего снять не удалось, так и
пишется в отчёте, а прогон идёт дальше.

Метод Maksi AI Solutions — версия для работ и услуг (с 15.11.2026). Метод наш; агентам других авторов не передаётся.

## Шаги

1. **Собрать лот в папку.** `python3 engine/scripts/lot.py get <номер объявления | номер лота | ссылка>`
   (Windows: `py engine\scripts\lot.py …`; запуск из корня базы). Площадку скрипт узнаёт сам по номеру или по ссылке. Всё ложится
   в `tenders/lots/<год>/<площадка>-<номер>/`: `docs/` (файлы и их текст в `docs/_text/`), `history.csv`
   (договоры заказчика по похожему предмету), `protocols/` (протоколы итогов прошлых конкурсов, госзакуп),
   `сводка.md` (факты одной страницей).
   - **Самрук.** Список файлов там закрыт защитой от ботов, обходить её нельзя. Поэтому: открыть ссылку
     из `сводка.md` в Chrome → кнопка «Документы» у объявления и у каждого лота → нажать каждый файл →
     `read_network_requests` с фильтром `filestorage` → взять UUID из адресов
     `eprocfilestorage/open-api/files/download/<UUID>`. Затем запустить
     `lot.py get <номер> --system samruk --uuid <UUID> <UUID> …`: файлы скачает скрипт. Вкладку закрыть.
     Без Chrome — сказать об этом в отчёте одной строкой и идти дальше без документов.
   - **Mitwork:** черновики документации без входа закрыты (401), окончательная документация скачивается.
     **МЭКС:** истории договоров заказчика в единой базе нет.
2. **Допуск.** Способ закупки: из одного источника → стоп, сказать и закончить. Приоритеты и ограничения
   (МСБ, отечественные). Приём заявок — дата и час, сколько осталось. Обеспечение заявки — сумма и форма.
3. **Документация построчно** (`docs/_text/`). Квалификационные требования: лицензии и категории, СРО,
   опыт аналогичных работ (за сколько лет, на какую сумму), кадры, техника, местное содержание. Объём:
   техспецификация, ВОР, сроки, место, гарантия. Проект договора: аванс, порядок оплаты, пени, штрафы,
   обеспечение исполнения, удержания, приёмка.
4. **Проходит ли её фирма.** Фирма — та, от которой она идёт (не сказала — по всем её фирмам из `firms/`).
   - Финустойчивость: `finstab.py calc firms/<фирма>/finstab.csv --lot <сумма лота> --kind works|services`
     по операции [[poschitat-finustoychivost]]. Цифр фирмы нет → в отчёте строка «не посчитано: нет цифр
     фирмы».
   - Лицензии и категории, опыт аналогичных работ, кадры, техника — против требований из шага 3, по
     карточке фирмы `firms/<фирма>/<фирма>.md`.
5. **История заказчика** (`history.csv`, `protocols/`).
   - Кто и почём выигрывал похожие работы, сколько раз закупка повторялась.
   - Что сорвалось: «не заключён», расторгнут.
   - По протоколам итогов: сколько было заявок, кого отклонили и за что, условные скидки, цены до и после.
   - Прошлую техспецификацию сверить с нынешней, если она есть в файлах.
6. **Конкуренты.** БИН из протоколов → `firm.py table <БИН> … --word <слово предмета>`, победители →
   `firm.py check <БИН>`: договоры года, РНУ, расторжения. Связанные фирмы — по одному адресу и
   руководителю.
7. **Условная цена владельца.** Скидки по правилу [[pravilo-uslovnye-skidki|условные скидки]]:
   налоги, территориальность (нужен ключ КГД; без него — по месту регистрации, помечено), аудит,
   отрицательные значения. Затем место среди прошлых участников.
8. **Вывод.**
   - Запас бюджета против прошлых цен.
   - Кого ждать на торгах.
   - Риски допуска.
   - Вердикт: заходить, рискованно или нет, и что именно решает.
9. **Записать.**
   - `анализ.md` в папке лота: выводы агента, каждый помечен как вывод.
   - Карточка `tenders/lots/<год>/<площадка>-<номер>.md` по операции [[zavesti-kartochku-lota]].
   - Коммит по путям: `сводка.md`, `history.csv`, `анализ.md`, карточка. Файлы площадки в git не идут.
10. **Отчёт в чат** — до 50 строк. Цифры только снятые, у каждой дата. Выводы помечены. Последняя строка —
    что не снято и почему.

**⏸ operator:** подавать или нет решает владелец. Подача и ЭЦП — тоже её действия, не агента.

## Крайние случаи

- Площадка не ответила (у госзакупа бывает 500, у МЭКС — 502). Повторить ту же команду через несколько
  минут: уже скачанное скрипт не перекачивает.
- Протокол итогов прошлого конкурса лежит в PDF: таблицы не разбираются, текст читать в `protocols/`
  или в `docs/_text/`.
- Документ — скан (в сводке у него 0 знаков текста): читать сам PDF постранично. Пропускать нельзя:
  у МЭКС техспецификации бывают сканами.
- В лоте несколько позиций: анализ — по каждой, вердикт — по тем, на которые владелец может зайти.

**Важно:** пустая клетка не значит «ноль». Пусто — значит не сняли, и в отчёте так и пишется.
